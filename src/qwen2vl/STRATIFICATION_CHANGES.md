# Text Difficulty Stratification Implementation

## Changes Made (Based on Analysis)

### 1. Removed Document Clustering

**Why:** Analysis showed cluster difficulty variance is only 0.64 (very low). All 68 clusters have similar quality, so clustering wasn't preventing quality imbalance - it was just reducing training data per fold.

**Before:**
- 68 document clusters
- K-fold=3 → each fold gets ~23 clusters
- 67% data per fold (~2,732 samples)

**After:**
- No clustering
- Single split → 90% data (~3,688 samples)
- **+956 more training samples** (+35% increase)

### 2. Switched to Single Split (k_folds=1)

**Why:** Analysis showed fold variance (0.909 vs 0.87-0.88) is NOT caused by data quality imbalance. It's random (annotation quality + initialization luck). K-fold lottery wastes data and time.

**Benefits:**
- ✅ 90% training data vs 67% per k-fold
- ✅ No fold lottery - one deterministic run
- ✅ 3x faster (one training run instead of three)
- ✅ Can still do checkpoint souping on this single run

### 3. Implemented Text Difficulty Stratification

**Why:** Analysis showed:
- Image difficulty variance: 0.024 (negligible)
- **Text difficulty variance: 8.9** (3x higher, what actually matters)
- Text difficulty ranges from 5.6 (pure boilerplate) to 56.0 (names+numbers+dates)

**Old Stratification (12 bins):**
```
digits (2) × uppercase (2) × lexical_diversity (3) = 12 bins
```

**New Stratification (60 bins):**
```
text_difficulty (3) × has_digits (2) × has_names (2) × text_length (5) = 60 bins
```

**What This Ensures:**

Train and val have the same distribution of:
1. **Text difficulty** (Easy/Medium/Hard)
   - Easy: "and of the said" (boilerplate)
   - Medium: Normal legal text
   - Hard: "London the 26: March 1669. ffor 100 Sterl:" (names+numbers)

2. **Has digits** (Yes/No)
   - Numbers are harder to transcribe (OCR digit errors)

3. **Has names** (Yes/No - indicated by uppercase)
   - Names are harder (not in language model prior)

4. **Text length** (5 bins: very short → very long)
   - Longer texts = more cumulative errors

### 4. Uses Pre-Computed Difficulty Scores

**How it works:**

1. Loads `dataset/text_difficulty.csv` (generated by `analyze_text_difficulty.py`)
2. Merges difficulty scores with training data
3. Creates 3 difficulty bins (easy/medium/hard) using quantiles
4. Stratifies to ensure balanced distribution

**Metrics used:**
- `difficulty_score`: Combined metric (names + rare words + numbers + special chars)
- `named_entity_score`: Presence of names
- `number_complexity`: Presence of numbers/dates

### 5. Handles Duplicates (Still Preserved)

**Unchanged:** Exact duplicate texts are still kept together in same split to prevent leakage.

From analysis: 40 duplicate rows identified and grouped.

## What If text_difficulty.csv Doesn't Exist?

The code has a **fallback**:

If `dataset/text_difficulty.csv` is not found, it will:
1. Compute basic features on-the-fly (digit density, uppercase ratio, lexical diversity)
2. Create a proxy difficulty score: `50*digits + 30*uppercase + 20*lexical_diversity`
3. Use that for stratification

**However**, this is less accurate than the pre-computed scores which use:
- Rare word detection
- Named entity estimation
- Historical spelling complexity
- Special character complexity

**Recommendation:** Always run `analyze_text_difficulty.py` first.
